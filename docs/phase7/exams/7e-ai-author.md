## Caveats and source tensions

- Managed Customer Service extensibility is the current **production-ready preview** procedure. The bundle uses its managed-agent tools, topics, context and fallback behavior; it does not portray the feature as universally GA or reuse obsolete plugin-management screens. Model, instructions and `msdyn_` topics are managed restrictions in that procedure.
- Case summaries are Customer Service-scoped; conversation-summary case actions use standalone Contact Center and the separately documented case-management dependency. No embedded conversation-summary promise is inferred.
- Copilot analytics is standalone in the current availability table. Throughput excludes voice/email; copied responses and daily unique users count different things. No causal productivity or accuracy claim follows from usage.
- Custom smart assist is separate from customer-facing Copilot Studio agents. The administration article excludes Entity Records Channel and records retirement of the built-in case/knowledge suggestions; the development sample does not override those current restrictions.
- Voice questions explicitly distinguish standard-harness Basic/classic execution from current Real-time configuration. Voice authoring is separate from Telephony. The real-time configuration table includes a text-LLM/Neural-TTS preview path; the transparency note describes the speech-to-speech path and is not used to universalize all model behavior. Regional/model availability must still be verified in a real rollout.
- Sensitive marking does not sanitize external writes, Dataverse persistence or custom logs. The source also has capability and first-question redaction limitations. No item promises complete transcript removal or end-to-end data erasure.
- Consent-based recording questions use supported inbound associated-agent scope. The sample can treat silence as implicit consent; the prompt alone does not prove affirmative consent. The examples apply a stated organization policy, not a legal rule.
- Secure external-contact capture settings are an explicitly available production-ready preview in q21. Consult and bridged-transfer controls are independent. Consent does not replace a per-contact capture override.
- Native context, static SIP UUI and SIP X-headers are different contracts. SIP questions explicitly use Direct Routing where required. Ordinary external PSTN transfer is not declared unsupported. UUI static text restrictions are not generalized to variable-backed outgoing X-headers. Incoming schema uses normalized lowercase `x-`; the article has an inconsistent later dot-notation example, so q24 relies on the explicit normalization and schema requirements rather than that example.
- The sensitive-data article sometimes calls SIP X-headers UUI headers. The dedicated UUI/X-header configuration pages determine the tested field contracts. The bundle never treats arbitrary X-headers and the static UUI property as interchangeable.
- Real-time trigger support is version/current-table scoped. Silence detection is distinct from VAD turn completion. The global-variable timeout conflict is not introduced into these new items; the pilot IVR caveat remains intact.
- Multilingual scenarios distinguish authored deterministic strings, generated conversation, explicit in-call User.Language switching and speech-region deployment. Browser-language detection is not assumed for telephone callers. General language-region TTS guidance does not override the current model-specific real-time voice ownership page.

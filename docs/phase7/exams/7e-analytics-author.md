## Applicability, conflicts and boundaries

- Supervisor workspace actions and embedded reporting are scoped to Contact Center standalone. Monitoring state differs for voice versus digital; elevated voice/video exclusions are scoped to the documented supervisor messaging-transfer feature, not every voice-transfer facility. Report authoring, bookmarks, action toggles and quality roles are different permissions.
- Quality evaluation uses the current framework. Email evaluation is preview and is not generalized into these conversation scenarios. Copilot credits, AI enablement and data-movement consent remain prerequisites where applicable; no licensing price or legal conclusion is invented.
- AI-assisted versus AI-agent question requirements, trigger-only participant scope, and trigger-versus-recurring Run history behavior are explicit current procedure claims. The plan article also has newer resolved-case trigger guidance; no universal claim is made that cases can only be recurring.
- Visual editing changes presentation of existing metrics; new logic/data calls for a model extension. Published visual customizations are organization-visible; bookmarks are a different artifact. Reset is permanent, while Resume editing continues authoring.
- The training unit says supervisors do not need Power BI authoring skills and describes embedded editing. It does not override the administration/product pages' Analytics Report Author requirement for shared report editing. Those permission pages control the questions.
- Historical and real-time model customization have different configuration pages and a shared navigation. A shared navigation does not give both pages ownership of each report entry.
- The current model-customization access procedure distinguishes Power BI Viewer from Member access for embedded supervisors, and requires Embed content in apps for the viewer group. This specific published procedure is the tested scope; no broad recommendation about every Power BI embed architecture or universal commercial license claim is made.
- The managed model is maintained by the service and should be read-only. Customer report copies are not automatically overwritten. Local composite extensions/relationships and custom measures preserve standard metric definitions. Hidden fields are not durable public contracts; no exposed field is declared universally immutable.
- The overview includes older wording about reports/model availability, while the setup page lists prerequisites across historical products. Questions use the supported standalone model/report paths and avoid inferring knowledge/unified-routing model customization from a prerequisite checkbox.
- Diagnostic automatic insights support out-of-the-box assignment methods. Raw custom ruleset telemetry is separately documented. This boundary is not proof that custom assignments succeeded or that all raw evidence is absent.
- One diagnostics data export configuration per source environment is the Power Platform page's stated constraint; it is not generalized to all Azure routing products.
- Ingestion/export, Dataverse telemetry read authorization, and Debug tab display are separate layers. App registration/federation, managed identity IDs, Monitoring Reader and default/environment app settings belong to the read/display path.
- Dashboard latency is explicitly scoped to the Application Insights out-of-the-box dashboard tab, which can lag by up to 15 minutes. The separate initial synchronization note is not converted into a guaranteed recovery deadline or a claim that all raw queries have that delay.
- The Debug federation guide includes a sample credential subject; questions instruct tracing the actual failed request rather than memorizing or universally copying a tenant-specific path.
